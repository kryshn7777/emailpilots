<objective>
Make the journey stream: a parse-once asset registry, per-chapter manifests, and a one-chapter-ahead prefetch driven by the same master scrub that drives the scenes. Then ship the QA tool the rest of the phase depends on — `?still=chN[.beat]`, which pins any authored frame and exports it at 2× DPR.

The insight from research is that fetching is not the jank source; parsing, PMREM generation and first texture upload are. So the prefetch does the *expensive* half a chapter early and the mount becomes a cache read. `AssetQueue` needs no changes at all — `add()` then `load(priority)` already skips completed items and only weights `critical` in the loader percent.

The still tool lands here, early, on purpose: every later chapter plan captures its own parity still, and Phase 4 (reduced-motion keyframes) and Phase 5 (OG crops) consume the same captures.

Purpose: EXP-05 (lazy-load one ahead, no pop-in) and D3-14 (the still utility).
Output: registry + manifests + prefetch wiring + `?still=`, with the manifest-integrity gate as a pure test.
</objective>

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | `?still=` parameter | mitigate | Single anchored regex; output is two clamped numbers (chapter int 1..7, beat float 0..1); the raw string is never stored, reflected, or used in the download filename — the filename is built from the parsed numbers (ASVS V5, continuing T-02-08) |

| T-03-SC | Tampering | npm/package installs | mitigate | Zero new packages — WebP encoding is the browser's own canvas encoder (research rejected a sharp/cwebp post-pass; this install's sharp path is broken per A3) |
